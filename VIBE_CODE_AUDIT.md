## Remediation Checklist

### High Priority

1. **Silent exception swallowing** — `src/sdr_module/dsp/recording.py:2490,2682,2695` catch `Exception` without even capturing the error variable. Add `as e` and log at minimum.

2. **Broad exception catches** — 54 occurrences of `except Exception as e`. For hardware drivers this is defensible, but protocol decoders and DSP code should catch specific exceptions (e.g., `ValueError`, `IndexError` for malformed data).

3. **Error UX gap** — GUI exception handlers log to console but don't notify the user. Add a status bar or notification system for user-visible errors.

### Medium Priority

4. **Test depth** — Add property-based testing (hypothesis) for DSP functions. Signal processing code benefits enormously from randomized input testing. Add fuzz testing for protocol decoders since they process untrusted radio data.

5. **WHY comments** — Add explanatory comments for non-obvious domain decisions. Example: why `POWER_HEADROOM_FACTOR = 1.5`? The comment exists in this case, but similar decisions throughout DSP code have no rationale.

6. **Exception chaining** — Use `raise NewException(...) from e` pattern when wrapping low-level exceptions. Currently no exception chaining exists anywhere.

### Low Priority

7. **Waterfall rendering performance** — Current implementation won't sustain real-time display at high sample rates. Consider NumPy-optimized or GPU-accelerated rendering for production use.

8. **State management architecture** — If the GUI grows more complex, consider a formal state management pattern to replace direct widget state.
